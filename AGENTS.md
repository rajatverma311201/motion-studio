# AGENTS.md: project rules for Motion Studio

You are working in a pnpm monorepo that produces animated software-engineering explainer videos (Motion Canvas) and a documentation site that lists and plays them (TanStack Start + Fumadocs). The owner is a senior Java/Quarkus engineer who makes YouTube videos. He reads every diff. Be precise and conservative.

## 0. How to behave (read this every session)

1. **Before doing anything**: read `PROGRESS.md` (if it exists), run `git status` and `git log --oneline -15`. Work must start from a clean tree. If the tree is dirty, stop and say so.
2. **Do exactly the task in the prompt file.** No extra refactors, no "while I am here" changes, no new dependencies that the prompt does not list.
3. **Never guess an API.** If a prompt tells you to read a doc URL, fetch it with your web-fetch tool and follow it. If a package API is unclear, read its `.d.ts` files in `node_modules`. Do not rely on memory for TanStack Start, Fumadocs, or Motion Canvas.
4. **Large files**: `transactions.tsx` is about 1300 lines. Never read a huge file whole into context. Use `grep -n`, then read 80 to 150 line ranges.
5. **Run the checks the prompt lists** (typecheck, tests, builds) and paste the real output summary in your final message. "Should work" is not a result.
6. **If blocked** after two honest attempts: stop, write the exact error and what you tried under `## Blocked` in `PROGRESS.md`, and end your turn. Do not invent workarounds like deleting tests, loosening types to `any`, or pinning random versions.
7. **Finish every step with**: update `PROGRESS.md`, then ONE git commit (or the commits the prompt lists) using the exact message given. Never `git push`. Never `git reset --hard`, never force anything. Never amend an earlier commit.

## 1. Repository layout (target state)

```
apps/studio        Motion Canvas app (Vite 4). Scenes + project files only.
apps/docs          TanStack Start + Fumadocs app (Vite 8).
packages/video-kit Reusable Motion Canvas building blocks. TypeScript source, no build step.
tools/snapshots    Playwright capture + pixel compare.
tools/scripts      Node scripts (sync-lessons, new-lesson).
```

Package names use the scope `@motion-studio/*` (`@motion-studio/studio`, `@motion-studio/docs`, `@motion-studio/video-kit`, `@motion-studio/snapshots`).

## 2. Hard version constraints (do not change)

- `@motion-canvas/*` packages: `^3.17.2`. The Motion Canvas Vite plugin only supports `vite 4.x || 5.x`. `apps/studio` uses **`vite ^4.5.14`**.
- `apps/docs` uses whatever Vite version `@tanstack/react-start` demands (currently `>= 8`) and Node `>= 22.12`.
- Because of the two rows above, **Motion Canvas code and TanStack Start code must never share a Vite config**, and `apps/docs` must never import `.tsx` files from `video-kit` (different JSX runtime).
- `apps/studio/package.json` must NOT contain `"type": "module"`. (It breaks the Motion Canvas plugin.) `apps/docs` and `tools/*` are ESM.
- Package manager: **pnpm**. Do not create `package-lock.json` or `yarn.lock`.

## 3. Naming and code style

- **Every file and folder name is kebab-case**: `code-panel.tsx`, `tree-view.tsx`, `define-lesson.ts`, `full-table-scan.tsx`. Allowed exceptions only: `README.md`, `AGENTS.md`, `PROGRESS.md`, `LICENSE`, dotfiles, `.meta` files (generated by Motion Canvas), config files with fixed names (`vite.config.ts`, `tsconfig.json`, ...), and TanStack Router route files (`__root.tsx`, `$slug.tsx`, `index.tsx`) inside `apps/docs/src/routes`.
- Section files inside a lesson are numbered: `01-intro.tsx`, `02-full-table-scan.tsx`.
- Identifiers: `camelCase` for functions and variables, `PascalCase` for classes, React components and types, `SCREAMING_SNAKE_CASE` only for true constants.
- Prettier style (match existing code): 2 spaces, single quotes, **no spaces inside braces** (`{a, b}`), trailing commas, `printWidth` 120, `arrowParens: avoid`. Only format files you create or touch.
- TypeScript `strict`. No `any` (use `unknown` + narrowing). Public functions get explicit return types. Options objects get a named `interface`.
- Prefer **named exports**. Default exports are allowed only where a framework requires them (Motion Canvas scene files `export default makeScene2D(...)` / project files `export default makeProject(...)`, TanStack route files, config files).
- Barrels: every folder in `packages/video-kit/src` has an `index.ts` that re-exports its public API. Consumers import from `@motion-studio/video-kit` only, never from deep paths.
- Comments explain **why**, not what. Every exported kit function has a short JSDoc with one usage example.

## 4. Motion Canvas rules and gotchas (verified the hard way)

- Scenes are generator functions. Use `yield*` for every animation. `all`, `sequence`, `delay`, `waitFor` come from `@motion-canvas/core`.
- Each section of a lesson builds its own root `Node`, animates, then removes it (`leave(root)`). This is what lets a lesson start at any section. Keep it that way.
- Nested `Txt` children do NOT flow inline in 3.17.2. The code panel therefore renders one `Txt` per token on a fixed monospace grid (0.6 em per glyph). Do not "simplify" this.
- Reactive props use functions: `points={() => ...}`, `width={() => ...}` with `createSignal`.
- `.meta` files are created by the editor next to every scene and project. **Commit them.** Never hand-edit them.
- The editor allows only ONE open browser page at a time per project (the editor rewrites `.meta`, which hot-restarts other pages). Playwright runs must be sequential.
- Console noise such as "Failed to fetch", font errors, or "Connection timeout when updating metadata" is harmless when offline or in a sandbox.
- Fonts are loaded by injecting a Google Fonts `<link>` (Space Grotesk + JetBrains Mono). Keep this behaviour unchanged unless a prompt says otherwise.
- Scenes are imported with a `?scene` suffix and projects are listed in `src/projects/<slug>.ts`. The Vite config uses the glob `project: ['./src/projects/*.ts']`.
- Studio dev server: `http://localhost:9000`. A project is opened at `/src/projects/<slug>`. A lesson can be started at section N with `#s=N` in the URL (dev only) or with the `startSection` variable (player).

## 5. Visual identity (must not drift)

Dark neubrutalism: background `#0B0B10`, light cream borders `#F4F1EA`, hard coloured offset shadows (no blur), accent colours lime `#C6FF3D`, pink `#FF4D8D`, cyan `#3DE3FF`, yellow `#FFD23D`, violet `#9B7BFF`, orange `#FF8A3D`, red `#FF4D4D`. Fonts: Space Grotesk (text), JetBrains Mono (labels/code). Videos have no voice-over: a caption bar ("NOTE") at the bottom narrates in text. Intro titles use a **solid lime slab with dark text and a violet hard shadow**; do not go back to white text with a pink/cyan shadow.

## 6. Commit message format (Conventional Commits)

`type(scope): summary` in lowercase imperative, e.g. `feat(video-kit): add code panel component`. Use the exact message the prompt gives. Types used: `chore`, `feat`, `refactor`, `test`, `docs`, `build`.

Notes: <anything the owner must know, max 5 bullets>
