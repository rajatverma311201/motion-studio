Most of the web hands you a string after login and trusts it on the next request. This course opens that string up: what a token contains, why anyone can read it, how a signature proves it was not changed, and where encoding stops and real encryption begins. If you want the whole idea in under a minute first, [a 60-second version is here](/docs/security/jwt-short).

## What you will learn

- HTTP is stateless; a JWT lets the client carry its identity with every request.
- A JWT is a header, a payload of claims and a signature, joined by dots.
- The parts are Base64URL: encoded, not encrypted, so anyone can read them.
- Encoding changes format, signing proves integrity and origin, encryption hides content.
- HS256 signs with a shared secret; RS256 and ES256 use a key pair published as JWKS.
- Always verify the signature and the claims exp, nbf, iss and aud, and pin the algorithm.
- Keep access tokens short-lived and never put secrets in the payload.
