Short definitions for the vocabulary of tokens, signatures and encoding.

| Term              | Meaning                                                                                |
| ----------------- | -------------------------------------------------------------------------------------- |
| Algorithm (`alg`) | The signing algorithm named in the header, e.g. `HS256`.                               |
| Audience (`aud`)  | The service the token is meant for.                                                    |
| Base64URL         | A URL-safe text encoding of bytes; it is not encryption.                               |
| Bearer token      | A token sent in the `Authorization` header; whoever holds it is treated as the bearer. |
| Claim             | A key-value fact in the payload, e.g. `sub` or `role`.                                 |
| Claim validation  | Checking `exp`, `nbf`, `iss` and `aud` after the signature.                            |
| Clock skew        | Small time differences between servers; claim checks tolerate a few seconds.           |
| Expiry (`exp`)    | The time after which the token must be rejected.                                       |
| HMAC              | A keyed hash (HMAC-SHA256) used to sign a JWT with a shared secret.                    |
| Header            | The first part: JSON that names the algorithm and token type.                          |
| Issuer (`iss`)    | The service that created the token.                                                    |
| JWE               | JSON Web Encryption: the encrypted flavour of a JWT, much rarer than JWS.              |
| JWKS              | JSON Web Key Set: a document publishing the public keys used to verify tokens.         |
| JWS               | JSON Web Signature: a signed JWT, the usual case.                                      |
| JWT               | JSON Web Token: three Base64URL parts joined by dots.                                  |
| Key pair          | A private key and its matching public key.                                             |
| `kid`             | Key id in the header; selects the right key from a JWKS document.                      |
| Private key       | The half of a key pair that signs; it never leaves the auth server.                    |
| Public key        | The half of a key pair that verifies; safe to publish.                                 |
| Payload           | The second part: JSON claims about the user and the token.                             |
| Refresh token     | A long-lived token stored server side, used to get a new short access token.           |
| Secret key        | The shared key only the server knows, used to sign and verify.                         |
| Signature         | The third part: proof that header and payload were not changed.                        |
| Subject (`sub`)   | The user or entity the token is about.                                                 |
| Token             | A string a server issues and later checks instead of a password.                       |
