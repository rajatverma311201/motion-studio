This site is the owner's recording companion, not a viewer-facing blog. It holds the voiceover notes for every chapter, the video tracker, the embedded player, and a copy-ready YouTube description. The videos themselves are Motion Canvas scenes: they live in `apps/studio`, share their visual building blocks through `packages/video-kit`, and are built into player bundles that this site embeds. Rendering the final MP4 is a separate step in the studio editor.

## What this site is for

- **Voiceover notes.** Each chapter has a `Say this` block with the points to speak while it plays.
- **Video tracker.** The home page lists every video with its status, chapters, duration, look, YouTube link and recording date.
- **The player.** The lesson page plays the chapter next to the notes, with the player sticky on wide screens.
- **The YouTube description.** Every lesson page builds the summary points and chapter timestamps into a text block with a Copy button.

The docs site uses the **stock Fumadocs look** with its light/dark toggle. Neubrutalism belongs to the videos only.

## The pipeline

1. **Write the scene.** `apps/studio/src/scenes/<slug>/scene.tsx` calls `defineLesson()` from `video-kit` with `chapters.json` and one generator per section. A project file in `apps/studio/src/projects/<slug>.ts` exposes it to the editor.
2. **Share the look.** Palette, fonts, the caption bar, code panels and tree components come from `packages/video-kit`. The kit is TypeScript source with no build step; both the studio and its tests consume it directly.
3. **Generate the docs data.** `pnpm sync` runs two scripts. `sync-themes` copies the theme ids, names and colours into `themes.json`; `sync-lessons` validates every `chapters.json` (including its optional `theme`, `mode`, `summaryPoints` and per-chapter `at` timestamps), resolves each lesson's look against `video.config.json`, and writes `lessons.json` with the points, timestamps and a `look: {theme, themeName, mode}` field. Neither script imports the kit into the docs app.
4. **Build the player bundle.** `pnpm videos:build` runs the sync and then the studio's Vite build. The studio writes straight into `apps/docs/public/videos`: one entry per project at `projects/src/projects/<slug>.js`, plus shared chunks.
5. **Play it on the docs page.** `<LessonVideo slug="<slug>" />` loads `/videos/projects/src/projects/<slug>.js` into the Motion Canvas player and shows the lesson's own render look. A chapter starts the bundle at that section and scrolls the matching `### NN ·` voiceover heading into view.
6. **Render the MP4.** Start the editor with `pnpm studio` (optionally in a look, see [Render a video in a look](/docs/production/render-in-a-look)), pick the project, check the console line `[video-kit] look: ...`, and press Render with the `Video (FFmpeg)` exporter. The MP4 lands in `apps/studio/output`. It is an artefact for YouTube; it is not committed and the docs do not depend on it.

## Commands

| Command                                           | What it does                                                                                |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `pnpm dev`                                        | Syncs generated data, then runs the studio bundle watcher and the docs dev server together. |
| `pnpm videos:build`                               | Syncs generated data and builds every project into `apps/docs/public/videos`.               |
| `pnpm build`                                      | `videos:build` followed by the docs production build.                                       |
| `pnpm sync`                                       | Regenerates `themes.json` and `lessons.json` without building anything.                     |
| `pnpm studio`                                     | Starts the editor; add `--theme <id>` and `--mode dark` or `--mode light` to pick a look.   |
| `pnpm snap:capture current` / `pnpm snap:compare` | Captures every section to PNG and compares it with the baseline.                            |

## Why two Vite versions

The Motion Canvas Vite plugin supports Vite 4 and 5 only. TanStack Start requires Vite 8. That is why there are two apps with two lockstep toolchains:

- `apps/studio` runs **Vite 4** with the Motion Canvas and ffmpeg plugins.
- `apps/docs` runs **Vite 8** with TanStack Start, Fumadocs and Tailwind 4.

The two configs never merge, and `apps/docs` never imports `.tsx` from `video-kit`; the two React runtimes and JSX transforms are not interchangeable. Data crosses the boundary only as JSON: `chapters.json` and the theme registry in, `lessons.json` and `themes.json` out.

<Callout type="warn" title="Do not upgrade the studio to Vite 6+">
  The Motion Canvas plugin will stop resolving projects and the editor will fail. Vite 4 is a deliberate pin, not an
  oversight.
</Callout>
