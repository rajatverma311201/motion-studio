---
title: Adding a lesson
description: Generate a lesson, preview it in the editor, write the voiceover notes, track its status and publish the YouTube description.
---

A lesson is three things that must agree: a scene in `apps/studio`, a `chapters.json` shared by the player and the docs, and an MDX recording page in `apps/docs/content/docs`. The generator creates the skeleton for all three.

## 1. Generate the skeleton

```sh
pnpm new:lesson mvcc-and-isolation "MVCC and Isolation Levels" --course databases
```

Arguments:

| Argument                 | Meaning                                                                                                                |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| `<slug>`                 | Kebab-case id. It becomes the project file, the scene folder, the video bundle name and the `video` frontmatter value. |
| `"<Title>"`              | Human title. Used for the page title, the intro slab and the HUD title (upper-cased).                                  |
| `--course <course-slug>` | Existing folder under `apps/docs/content/docs`, e.g. `databases`.                                                      |
| `--chapters <n>`         | Optional chapter count, default `4`.                                                                                   |
| `--theme <id>`           | Optional theme id written into `chapters.json`, e.g. `tokyo-night`. Validated against the registry.                    |
| `--mode dark\|light`     | Optional mode written into `chapters.json`; the theme's default applies when omitted.                                  |

The generator refuses to run if the slug is not kebab-case, the course folder does not exist, or any target file already exists. It never overwrites.

It creates:

```text
apps/studio/src/projects/<slug>.ts
apps/studio/src/scenes/<slug>/chapters.json
apps/studio/src/scenes/<slug>/scene.tsx
apps/studio/src/scenes/<slug>/sections/01-intro.tsx
apps/studio/src/scenes/<slug>/sections/02-chapter-2.tsx
...
apps/docs/content/docs/<course>/<slug>.mdx
```

It also appends the slug to the course's `meta.json`, runs `pnpm sync:lessons`, and prints the editor URL plus the file list. Every generated chapter is a valid, previewable section: the intro shows a title block, the others show a chip and a caption, and each ends with `leave(root)`.

The new page starts at `status: outline`, `duration: TBD`, and `summaryPoints: ["TODO"]`. Nothing is invented for you.

## 2. Preview in the editor

```sh
pnpm studio:dev
```

Open `http://localhost:9000/src/projects/<slug>`. To start at a section, add the dev-only hash:

```text
http://localhost:9000/src/projects/mvcc-and-isolation#s=2
```

`#s=N` is a **zero-based section index**: `#s=0` is the intro, `#s=2` is the third section. The value is clamped into `[0, chapters.length - 1]`. The player uses the `startSection` variable for the same purpose on the docs page.

Only one editor page may be open per project: the editor rewrites the `.meta` files, which hot-restarts other pages. Close the others before running Playwright.

## 3. Map chapters to the video

`chapters.json` is the single source of truth. Chapter `i` corresponds to:

- the `i`-th entry of `sections` in `scene.tsx`,
- the `i`-th HUD pill,
- the `i`-th `### NN ·` voiceover heading on the docs page,
- section index `i` in `#s=N` and in the player's chapter list.

The counts must match exactly. `defineLesson()` throws at definition time when `sections.length !== chapters.length`, and the message names the slug and both counts. Chapter names are short and upper-case (`INTRO`, `B+TREE INSERT`); the colour is a palette key, not a hex value. The `summary` is one sentence shown in the chapter cards.

To change a chapter after generation, edit `chapters.json` and the matching section file together, then run:

```sh
pnpm sync:lessons
```

`pnpm dev` runs the sync once at startup; it does not watch `chapters.json`. Restart `pnpm dev` after editing it if you need the docs chapter cards to update.

## 4. Fill the recording page

Open `apps/docs/content/docs/<course>/<slug>.mdx`. The template is:

```mdx
---
title: ...
description: ...
video: <slug>
status: outline
duration: TBD
---

<LessonVideo slug="<slug>" />

## Summary points

<SummaryPoints slug="<slug>" />

## Chapters and voiceover notes

### 01 · INTRO

<VoiceoverNotes>

- TODO: first thing to say
- TODO: second point

</VoiceoverNotes>

(repeat per chapter, same numbering and names as chapters.json)

## YouTube description

<YoutubeDescription slug="<slug>" />
```

- `status` is one of `outline`, `animated`, `rendered`, `voiced`, `published`.
- `duration` is the final length (`12:40`) or `TBD` until the render exists.
- `youtube` is added when the video is live.
- `recorded` is the voiceover date (`YYYY-MM-DD`).

The five statuses describe the pipeline:

| Status      | Meaning                                    | Next action                    |
| ----------- | ------------------------------------------ | ------------------------------ |
| `outline`   | The skeleton exists; the notes are TODO.   | Write the notes.               |
| `animated`  | The sections are animated and previewable. | Render the MP4.                |
| `rendered`  | The MP4 exists.                            | Record the voiceover.          |
| `voiced`    | The voiceover is recorded.                 | Publish and add the link.      |
| `published` | The video is on YouTube; `youtube` is set. | Nothing; keep the notes fresh. |

`pnpm status` prints the slug, status, duration and YouTube link for every lesson page.

## 5. Fill summary points and timestamps

`summaryPoints` lives in `chapters.json`, not in the MDX page. It is an array of 3 to 8 short strings; the page and the YouTube description both read it. The generator writes `["TODO"]`; replace it before publishing.

```json
{
  "slug": "mvcc-and-isolation",
  "title": "MVCC AND ISOLATION",
  "summaryPoints": [
    "Why readers and writers need separate versions of a row.",
    "How a snapshot makes a read repeatable."
  ],
  "chapters": [{"name": "INTRO", "color": "lime", "summary": "One sentence."}]
}
```

Each chapter gets an optional `at` timestamp in `m:ss` or `h:mm:ss`. Fill these in after the final render, when the chapter boundaries are fixed:

```json
{"name": "INTRO", "color": "lime", "summary": "One sentence.", "at": "0:00"}
```

`pnpm sync:lessons` rejects malformed timestamps and summary arrays. Leave `at` out until the render exists; the YouTube description shows `--:--` and a `timestamps missing` warning in the meantime.

## 6. Write the voiceover notes

Each chapter has a `Say this` block. The bullets are what you say while that chapter plays, not a summary of the visuals. Three to six short sentences is the useful range. Use `- TODO: ...` when the material is too thin to write something true.

The player is sticky on wide screens, so you can watch the chapter while reading the notes. Clicking a chapter restarts the video at that section and scrolls the matching `### NN ·` heading into view.

## 7. Copy the YouTube description

The last section of the lesson page builds the description from the page description, `summaryPoints`, and every chapter with its `at` timestamp. Press **Copy** and paste it into YouTube. The chapter list is already in the right format:

```text
In this video:
- Why readers and writers need separate versions of a row.

Chapters:
0:00 Intro
1:12 The problem
```

The empty line at the end is reserved for links.

## 8. Publish

Set the status as the video moves through the pipeline, and when the upload is done:

```yaml
status: published
youtube: https://youtu.be/...
recorded: 2026-11-02
```

A published page needs a built bundle. `pnpm videos:build` creates `apps/docs/public/videos/projects/src/projects/<slug>.js`; without it the player shows "Video bundle not found". `pnpm build` does both in the right order.

## 9. Commit the editor metadata

Opening a scene or a project in the editor writes `.meta` files next to it:

```text
apps/studio/src/scenes/<slug>/scene.meta
apps/studio/src/projects/<slug>.meta
```

Commit them. They hold the editor's saved state and are part of the project; never hand-edit them and never add them to `.gitignore`. The standalone `.meta` files are also excluded from Prettier and ESLint on purpose.

## 10. Run the checks

```sh
pnpm check # typecheck + lint + tests + format
pnpm build # videos + docs
pnpm status
```

`pnpm check` enforces the file-naming rules: every new file must be kebab-case, except the numbered section files (`01-intro.tsx`) and the TanStack route files.
